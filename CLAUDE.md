# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Baltic Trust Layer — a hackathon prototype that scores GNSS/AIS trustworthiness for the Gulf of Gdańsk. It ingests AIS position reports (simulated, live from AISStream.io, or replayed from CSV), runs them through detector heuristics for two evidence families (declared integrity vs. physical geometry), aggregates detections into H3 hexagon cells per 15-minute time window, and serves a trust score (`TRUSTED` / `LIMITED` / `DO_NOT_USE` / `NO_DATA`) per hex over a WebSocket to a single-page dashboard.

Code comments and identifiers are largely in Polish (this was built for a Polish maritime-security hackathon, referencing an ICEYE × Impulse Institute report on Baltic security incidents like MV SUN, Eagle S, Yi Peng 3).

## Running the app

```bash
python -m venv .venv && source .venv/bin/activate   # if not already set up
pip install -r requirements.txt
cp .env.example .env   # then edit MODE / AISSTREAM_API_KEY as needed
python app.py          # serves on http://0.0.0.0:8000
```

There is no test suite, linter, or build step in this repo — there's nothing to run beyond starting the server and hitting it manually or via the dashboard at `/`.

### Modes (set via `MODE` in `.env`)

- `demo` (default) — `DemoSimulator` generates ~20 simulated vessels around the Gulf of Gdańsk with scripted anomaly scenarios (jamming, spoofing cluster, on-land position, kinematic jump, MV-SUN-style loitering, shadow-fleet AIS gaps). Runs at 60x speedup (1 real second = 60 simulated seconds).
- `live` — connects to AISStream.io over WebSocket using `AISSTREAM_API_KEY`, filtered to the Gulf of Gdańsk bounding box. Falls back to demo mode if the key is missing/unset.
- `replay` — reads AIS reports from a CSV file at `REPLAY_FILE` and replays them with a small throttle. Falls back to demo mode if the file doesn't exist.

## Architecture

Data flows in one direction: **source → `AISReport` → `TrustEngine.process_report()` → detections → WebSocket broadcast → dashboard**.

- **`app.py`** — FastAPI app and process orchestration. Picks the data source in `lifespan()` based on `MODE`, feeds every position report through the module-level `process_report()` callback and every static message through `process_static()`, and fans out results to all connected WebSocket clients via `broadcast()` (static messages are not broadcast on their own — they surface as vessel identity and as FR-006 detections). Holds the only global mutable state: `trust_engine`, `ws_clients`, `stats`.
- **`models.py`** — all shared dataclasses/enums: `AISReport` (raw per-vessel report + integrity flags), `StaticReport` (AIS type 5 / `ShipStaticData` — identity, IMO, hull dimensions, no position), `Detection` (one detector's output), `HexCell` (one H3 cell's aggregated score, carrying both `detection_count` and the `episode_count` that actually feeds scoring), `TimeWindow` (15-min bucket of hex cells). `DetectionType` values are grouped into two `DetectorFamily` values (`declared_integrity` vs `physical_geometry`) — this split is structural and shows up throughout scoring and the dashboard, not just cosmetic categorization.
- **`trust_engine.py`** (`TrustEngine`) — the core aggregator. Buckets reports/detections into 15-minute `TimeWindow`s keyed by H3 index (resolution 7, `H3_RESOLUTION`). On window close (`_finalize_window`), computes a 0–100 trust score per hex from `DETECTION_WEIGHTS` × `CONFIDENCE_MULTIPLIER`, normalized by vessel count, then maps score → `TrustLevel` via `TRUST_THRESHOLDS`. Scoring runs on *deduplicated episodes*, not raw detections (`_dedupe_episodes`): detectors fire once per report, so one anomaly yields hundreds of detections per window and the score would saturate at 100 for any hex with any anomaly. Single-vessel episodes are keyed by type + MMSI; area episodes (multi-MMSI, e.g. convergent cluster) by type alone, since their membership fluctuates between reports. `MIN_VESSELS_FOR_SCORE` gates only the `declared_integrity` family — one vessel's RAIM flag says nothing about an area, whereas `physical_geometry` evidence (on land, kinematic jump, loitering, position loss) counts regardless of fleet size, and any such evidence floors the score at the `TRUSTED` threshold so a hex with a confirmed physical anomaly can never read as `TRUSTED`. A hex is `NO_DATA` only when it has too few vessels *and* no geometry evidence. Both aggregation paths — `_finalize_window` and `get_current_hex_snapshot()` (which recomputes on-demand for the *unfinalized* current window, used for live dashboard state) — go through the shared `_evaluate_hex()`, so scoring changes land in both; the surrounding cell-building code is still near-duplicated. `get_brief()` derives one overall recommendation for the whole area: worst hex wins (any `DO_NOT_USE` hex dominates the whole brief).
- **`detectors/integrity_detectors.py`** — per-report checks on *declared* AIS integrity fields: RAIM off, low position accuracy, anomalous UTC-second values (manual/dead-reckoning/inoperative), plus a stateful `IntegrityDegradationDetector` that flags a whole hex if >30% of its reports in a window have integrity issues.
- **`detectors/geometry_detectors.py`** — per-report checks on *physical plausibility*: position on land (outside port masks), kinematic jump (implied speed >60 kn between consecutive reports from the same MMSI, via stateful `KinematicJumpDetector`), convergent cluster (≥3 distinct MMSI within 50m in 2 minutes — spoofing signature, via `ConvergentClusterDetector`), proximity/loitering near critical subsea infrastructure (`InfraProximityDetector`, modeled on the MV SUN incident near SwePol Link), and position loss (`PositionLossDetector`, FR-006: no position report for >5 min while static messages keep arriving — a live transponder with its position silenced, the shadow-fleet signature). `PositionLossDetector` is fed positions inside `run_geometry_checks()` and static messages via `TrustEngine.process_static()`; it self-throttles its sweep and is about *absent* reports, so the incoming report only serves as its clock.
- **`data/gdansk_bay.py`** — static geometry: bounding box, hand-drawn port-mask polygons (so "on land" detection excludes docks/quays), a simplified coastline heuristic (`is_likely_on_land`), and geometry helpers (`haversine_km`, point-to-segment/route distance) used by the geometry detectors.
- **`data/iceye_context.py`** — reference data from the ICEYE × Impulse Institute report: subsea cable/pipeline routes (SwePol Link, Baltic Pipe, C-Lion1, EstLink 2, Balticconnector), real incident writeups (MV SUN, Eagle S, Yi Peng 3, Balticconnector), and Baltic-wide statistics. Route coordinates are hand-approximated and have been wrong before: SwePol Link's southern half ran overland (fixed — it now makes landfall near Ustka), and Baltic Pipe still runs through the Gulf of Gdańsk although the real pipeline lands at Niechorze. Check a route against actual geography before building a scenario on it — `demo_simulator.py`'s `mv_sun_loiter` inherited the SwePol error and rendered a tanker loitering over farmland — used both by `InfraProximityDetector` and for dashboard/presentation context.
- **`demo_simulator.py`** (`DemoSimulator`) — defines the simulated fleet (`FLEET`) and routes (`ROUTES`), moves vessels along waypoints each tick, and injects the anomaly behavior per vessel's `anomaly` field (jamming, spoofing_cluster, on_land, kinematic_jump, mv_sun, shadow_fleet). This is the primary way to exercise every detector without a live feed — read this file to understand what each anomaly scenario is supposed to trigger downstream.
- **`ais_client.py`** (`AISStreamClient`) — WebSocket client for AISStream.io with auto-reconnect (exponential backoff), parses `PositionReport` messages into `AISReport`, pulling integrity fields (RAIM, PositionAccuracy, UTC second) from the raw message, and `ShipStaticData` into `StaticReport`. Static messages are *not* yielded by `stream_reports()` — they go out through the separate `static_callback` so the iterator keeps one type.
- **`static/index.html`** — single-file dashboard (HTML/CSS/JS, no build step). Connects to `/ws`, renders hex trust scores and live detections. The detection list aggregates *episodes*, not raw detections, using the same key rule as the engine (single-vessel: type + MMSI; area: type alone) with a `×N` repeat counter — detections arrive at ~86/s, so a flat list of the last 50 turned over every 0.6 s and rare types (`position_loss`, `position_on_land`) were never readable. Rendering is throttled to 4 Hz and the least-recently-active episode is evicted at the cap. Not driven by REST polling — the WebSocket `init`/`report`/`hex_update`/`brief` message types (defined in `app.py`) are the primary data contract; the `/api/*` REST endpoints exist mostly as secondary/debug access to the same state (`trust_engine.get_current_hex_snapshot()`, `get_brief()`, `all_detections`, `history`).

## Key invariants to preserve when editing

- `TrustLevel` is a closed 4-value enum (`trusted`/`limited`/`do_not_use`/`no_data`) — the brief and dashboard logic assume exactly these values exist, don't add more without updating `_score_to_level`, `get_brief`, and the frontend.
- Detector functions return `Detection | None` (or `list[Detection]` for multi-detection checks like `InfraProximityDetector`) and never raise on bad input — they're called once per incoming report in a hot loop.
- `process_report()` / `process_static()` in `app.py` swallow and log every exception via `log_processing_error()` (first 5 with traceback, then every 100th, counted in `/api/stats` as `processing_errors`). An exception escaping into the asyncio task kills the data source silently — that is how a `broadcast()` bug once hid. `CancelledError` is re-raised so shutdown still works.
- `TrustEngine._all_detections` is a bounded buffer (`_max_all_detections`, 1000) — the cumulative total lives in `_detections_seen` and is what `get_brief()` reports. Detections arrive at ~336k/h, so nothing in the engine may retain them without a cap; `_history` is bounded separately by `_max_history` (48 windows) and the two together plateau at ~100 MB RSS.
- Stateful detectors (`KinematicJumpDetector`, `ConvergentClusterDetector`, `InfraProximityDetector`, `PositionLossDetector`, `IntegrityDegradationDetector`) hold per-MMSI or per-hex state across calls; `TrustEngine` owns one instance of each and resets `IntegrityDegradationDetector` on window finalize, but the geometry detectors' state persists across windows (only reset via the module-level singletons' `.reset()`, which currently isn't called anywhere in the finalize path) — be aware of this asymmetry if changing window-boundary behavior.
